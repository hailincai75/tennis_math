# Tennis Math — Elsa 比赛统计 App 开发规划

## 1. 已确定的决策

| 项目 | 决定 |
|---|---|
| 形态 | PWA 网页应用。在 iPhone Safari 里“添加到主屏幕”，打开后全屏运行，可离线 |
| 数据 | 只存在手机本地（IndexedDB），没有账号和服务器端数据库 |
| 代码托管 | 静态文件放在免费 HTTPS 托管上（GitHub Pages 或 Cloudflare Pages）。只托管程序本身，比赛数据不会上传 |
| 比赛类型 | 第一版只做单打 |
| 默认记录粒度 | 标准模式：发球结果 + 这一分怎么结束。快速模式作为备选 |
| 开发环境 | Windows |

## 2. 技术栈

- **Vite + React + TypeScript**：主框架，类型系统能防止统计口径出错
- **vite-plugin-pwa**：生成 Service Worker 和 manifest，让 app 离线可用、可装到主屏
- **Dexie.js**：封装 IndexedDB，负责本地存储和数据库版本迁移
- **Recharts**：画趋势图、势头图
- **Vitest**：给记分引擎和统计计算写单元测试（这是整个 app 最容易出错的部分）
- 不用 UI 组件库，自己写 CSS，针对 iPhone 竖屏和大按钮优化

### iOS PWA 需要注意的地方
1. **主屏 app 和 Safari 的存储是分开的**：一定要从主屏图标打开 app 记比赛，不要在 Safari 标签页里记。
2. **防止数据被系统清理**：启动时调用 `navigator.storage.persist()`。另外做“导出备份”功能，并定期提醒用户备份（比如每记完 5 场提醒一次）。
3. **比赛中保持屏幕常亮**：尽量用 Screen Wake Lock API；不支持时提示用户把自动锁定时间调长。
4. **iOS 不支持网页震动**，点击反馈改用视觉效果（按钮闪一下、显示 toast）。
5. 第一次安装和每次更新需要联网，之后完全离线。

## 3. 核心设计：用“每一分”作为唯一数据来源

数据库里**只存每一分的原始记录**。比分、谁发球、是不是破发点、所有统计，都由程序根据这些记录**实时推算**，不单独存储。

好处：
- **撤销**：删掉最后一分就行，比分自动正确
- **改错**：改了中间某一分，后面的比分全部自动重新推算
- **统计口径可以随时改**：改了算法，所有历史比赛重新计算，不用迁移数据

```
Point[]  ──►  记分引擎 (scoring engine)  ──►  每一分的比赛情境 (比分、发球方、是否破发点…)
                                         └─►  统计引擎 (stats engine)  ──►  单场统计 / 跨比赛分析
```

## 4. 数据模型

```ts
type Side = 'elsa' | 'opp';

interface Opponent {
  id: string;
  name: string;
  hand?: 'R' | 'L';
  utr?: number;          // 或者其它评级
  club?: string;
  notes?: string;
}

interface MatchFormat {
  setsToWin: 1 | 2;                  // 1 局定胜负 / 3 盘 2 胜
  gamesPerSet: 4 | 6 | 8;            // 短盘 4，标准 6，Pro set 8
  tiebreakAt: number;                // 例如 6 表示 6-6 时抢七
  tiebreakPoints: 7 | 10;
  finalSet: 'full' | 'matchTiebreak10';  // 决胜盘打完整一盘还是抢十
  noAd: boolean;                     // 金球
}

interface Match {
  id: string;
  date: string;                      // ISO 日期
  opponentId: string;
  event?: string;                    // 赛事名称
  round?: string;                    // 轮次
  surface?: 'hard' | 'clay' | 'grass' | 'indoor';
  location?: string;
  format: MatchFormat;
  firstServer: Side;
  status: 'in_progress' | 'completed' | 'retired' | 'abandoned';
  recordingMode: 'quick' | 'standard';
  notes?: string;
  createdAt: number;
  updatedAt: number;
}

type PointEnding =
  | 'ace'            // 发球直接得分（对手没碰到球）
  | 'service_winner' // 对手碰到球但没回过来
  | 'double_fault'
  | 'winner'
  | 'unforced_error'
  | 'forced_error';

interface Point {
  id: string;
  matchId: string;
  seq: number;                       // 第几分，从 0 开始
  // 标准模式下记录：
  firstServeIn?: boolean;            // 一发是否进
  ending?: PointEnding;
  endedBy?: Side;                    // 打出最后一拍的人（制胜分或失误是谁打的）
  // 快速模式或补录时，只记谁赢：
  winner: Side;                      // 标准模式下由 ending + endedBy 推出，也一起存下来方便查询
  rallyLength?: 'short' | 'medium' | 'long';  // 可选：1-4 拍 / 5-8 拍 / 9 拍以上
  stroke?: 'FH' | 'BH' | 'volley' | 'overhead' | 'drop' | 'lob';  // 留给以后的详细模式
  note?: string;
  timestamp: number;
}
```

规则：`winner` 一律以 `ending + endedBy` 为准推出。ACE、发球直接得分、制胜分算打出最后一拍的人赢；双误、非受迫性失误、受迫性失误算打出最后一拍的人输。

## 5. 记分引擎（scoring engine）

输入 `MatchFormat`、`firstServer`、`Point[]`，输出每一分的情境：

- 当前盘分、局分、分数（0/15/30/40/AD，或者抢七里的分数）
- 发球方，抢七中按“1-2-2”轮换
- 是否是破发点、局点、盘点、赛点、平分（deuce）、抢七
- 比赛是否结束、谁赢

需要用单元测试覆盖的情况：
- 标准局（含 deuce 和占先），以及金球
- 6-6 抢七、短盘 4-4 抢七
- 抢十代替决胜盘
- 抢七之后，下一盘由谁先发球
- 撤销和改中间某一分之后，比分要重新推算正确
- 中途退赛（retired）

## 6. 统计口径（单场，Elsa 和对手各算一份）

| 分类 | 指标 | 计算方法 |
|---|---|---|
| 发球 | 一发进球率 | 一发进的分 ÷ 发球分 |
| | 一发得分率 | 一发进且赢的分 ÷ 一发进的分 |
| | 二发得分率 | 二发分里赢的分 ÷ 二发分（双误计入分母） |
| | ACE / 双误 | 次数 |
| | 发球局保发率 | 保发局数 ÷ 发球局数 |
| 接发 | 接一发得分率、接二发得分率 | 从对手角度反过来算 |
| | 破发转化率 | 破发成功次数 ÷ 获得的破发点数 |
| 关键分 | 破发点挽救率 | 挽救的破发点 ÷ 面对的破发点 |
| | deuce 分胜率、抢七分胜率 | |
| | 30-30 之后的分 / 局点和盘点胜率 | |
| 每分结果 | 制胜分、非受迫性失误、受迫性失误 | 次数，以及占总分数的比例 |
| | 制胜分 − 非受迫性失误 | 衡量“主动得分”的净值 |
| 回合 | 短/中/长回合各自的胜率 | 只统计记了回合长度的分 |
| 总体 | 总得分率、最长连续得分、最长连续丢分 | |
| 势头 | 逐分累计的得分差曲线，标出破发点 | |

## 7. 跨比赛分析

- **趋势**：任意指标按时间画折线图，比如一发进球率、非受迫性失误比例
- **对手**：和同一个对手的战绩、比分，以及每场的关键指标对比
- **分组比较**：按场地、赛事级别、对手评级区间、时间段（比如这个月和上个月）
- **胜负对比**：赢的比赛和输的比赛平均指标差多少，找出“决定胜负的指标”
- **自动提示**：用规则引擎生成，不用 AI。比如“最近 5 场非受迫性失误比例比之前高了 8%”“破发点挽救率低于整体发球得分率”

## 8. 页面结构

1. **首页**：最近比赛列表、正在进行的比赛（点进去继续记），右上角“新比赛”
2. **新比赛**：选对手（可以现场新建）、赛制（提供常用模板）、先发球方、场地、赛事
3. **记分页**（最重要，要能单手操作）
   - 顶部：大号比分牌（盘/局/分），标出发球方和是否破发点
   - 发球阶段：`一发进` / `一发失误` → `二发进` / `双误`；另外有 `ACE` 和 `发球直接得分` 快捷键
   - 回合结束：`Elsa 制胜分` / `Elsa 非受迫` / `Elsa 受迫`，以及对手的同样三个按钮
   - 底部：撤销、加备注、暂停/结束比赛
   - 每分点 2–3 下完成
4. **单场统计页**：比分总结、发球/接发/关键分卡片、势头图、逐分列表（可以点开修改）
5. **分析页**：趋势、对手、分组比较、自动提示
6. **对手页**：对手列表和对战记录
7. **设置页**：默认赛制、默认记录模式、导出/导入备份（JSON 和 CSV）、存储状态

## 9. 开发里程碑

| 里程碑 | 内容 | 完成标准 |
|---|---|---|
| **M0 基础设施** | Vite + React + TS + PWA 脚手架；部署到 GitHub Pages | iPhone 能添加到主屏、打开、飞行模式下也能打开 |
| **M1 记分引擎** | `scoring.ts` 和完整单元测试 | 第 5 节列出的情况全部通过测试 |
| **M2 数据层** | Dexie 表结构、增删改、`storage.persist()` | 杀掉 app 重新打开，数据还在 |
| **M3 记分页** | 新比赛流程、记分页、撤销、备注、中途退出后继续 | 在场边完整记完一场真实比赛 |
| **M4 单场统计** | `stats.ts` 和测试、统计页、势头图、逐分修改 | 手算一场比赛的统计结果，和 app 算的一致 |
| **M5 跨比赛分析** | 趋势、对手、分组、胜负对比、自动提示 | 用 5 场以上数据能看出有意义的趋势 |
| **M6 备份和打磨** | JSON 导出导入、CSV 导出、备份提醒、屏幕常亮、深色模式 | 导出后清空数据再导入，数据完全恢复 |

建议按顺序做。M1 和 M4 的引擎是纯逻辑，可以先在电脑上用测试验证，再做界面。
